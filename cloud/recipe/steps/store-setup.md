## This step: store setup (recipe phase 3)

Read `qa/state/inventory.json` and `qa/state/theme.json` first. Then run the four agents below **concurrently, in the background** (sub-agents via the `Agent` tool, with the models listed under "Sub-agent models"), followed by the menu work. Wait for all of them before you finish. Each agent gets its whole paragraph below in its prompt.

`qa/state/handles.json` has one writer — you: have Agents A, B and D return their entries (or write them to `qa/state/handles-a.json` / `-b` / `-d`), and once all have finished, merge them into the one array described under Agent A (one entry per route) and delete the part files. Concurrent agents writing the same file lose each other's entries.

**Agent A — Pages:** For each entry in the inventory `pages` that is a content page (not the home page — it renders through `index.json` — and not a product/collection route, which Agent D seeds), `POST /admin/api/2025-01/pages.json` with `handle` = the entry's `shopify_handle` and `template_suffix` = the entry's `template` without the leading `page.` and the trailing `.json` (`page.{{PREFIX}}_our_team.json` → `{{PREFIX}}_our_team`) — the page step writes exactly that template, so a different suffix renders the page through the wrong template. Idempotent: look the handle up first and update instead of duplicating. Verify each returns 201 (or 200 on update) and the page resolves at `/pages/<handle>`. Save the route → handle → template map to `qa/state/handles.json` so the page steps can wire `shopify://pages/<handle>` links correctly. Write it as an array, one entry per React route:

```json
[
  { "route": "/", "handle": "", "shopify_path": "/", "template": "templates/index.json" },
  { "route": "/about", "handle": "about", "shopify_path": "/pages/about", "template": "templates/page.{{PREFIX}}_about.json" }
]
```

**Agent B — Blog + articles:** `POST /admin/api/2025-01/blogs.json` for the field-notes blog. For each article in the React data file, `POST /admin/api/2025-01/articles.json` with title, body_html, tags, published_at, image. Idempotent: reuse the blog if its handle exists and skip articles whose handle already exists (a retried step must not duplicate them). If the blog's React route is not already a page in the inventory, add it to `qa/state/handles.json` with `"shopify_path": "/blogs/<blog-handle>"`; if it is, leave Agent A's entry — that page step builds it.

**Agent C — Files + metafields + policies:** For each entry in the inventory `images`, run `stagedUploadsCreate` + `fileCreate` (GraphQL). Build a `react_path → cdn_url` map at `qa/state/images.json` (if it exists already, keep its entries and upload only what is missing). Swap dead source URLs (see the dead-media lesson) rather than uploading broken media, and note each swap. Define metafield definitions for any custom fields React uses on products/articles. Create boilerplate privacy / ToS / refund policies if the footer references them.

**Agent D — Catalog (products + collections):** If the inventory contains product or collection pages (React routes under `/products/*`, `/collections/*`, or PDP/PLP-style pages), seed matching catalog objects — QA maps `/products/<handle>` and `/collections/<handle>` straight through, so an unseeded catalog 404s every one of those routes. For each React product page: Admin GraphQL `productCreate` (or `productSet`) with the React title, description as body HTML, `handle` equal to the React slug, the visible price as the variant price, and images wired from the `qa/state/images.json` CDN map; then publish it to the Online Store channel (`publishablePublish` with the publication ID from `publications(first: 10)`). For each React collection page: `collectionCreate` with matching title/handle/description/image, add the products it visibly contains, and publish it the same way. Idempotent: look up by handle first (`productByHandle` / `collectionByHandle`) and update instead of duplicating. Add every created route to the `qa/state/handles.json` entries (`{ "route": "/products/<slug>", "handle": "<handle>", "shopify_path": "/products/<handle>", "template": "templates/<the inventory template>" }`, same for collections) so QA maps them. Requires `write_products` + `write_publications` scopes — on 403, apply the same blocker rule as menus (below); do not silently skip, since every catalog page would then score as missing.

Agents C and D both depend on images: let Agent D wait for `qa/state/images.json` (or upload the product images itself through the same `stagedUploadsCreate` + `fileCreate` pattern and merge them into the map).

**Menu work (Agent A continued):** Run `node seed/create-menus.mjs` (written by the bootstrap step) to upsert the nav menus via the GraphQL `menuCreate` / `menuUpdate` mutations (REST `menus.json` does not exist). Mirror the React Navbar + Footer exactly, including nested children. Use **dedicated handles** (`{{PREFIX}}-main-menu`, `{{PREFIX}}-footer`) — do NOT overwrite the store-wide `main-menu` / `footer`, since the published theme renders those. Verify afterwards that the rendered header/footer on the dev preview come from `linklists` (count the links in the DOM), not from the fallback branch.

**Scope errors:** if the menu mutations answer `403 / scope missing`, write `qa/reports/BLOCKED.md` asking the user to add `write_online_store_navigation` to the custom app, `Release` a new version, re-install, and resume (for the catalog: `write_products` + `write_publications`). Do not silently skip: a missing menu means the header falls back to hardcoded links and the merchant cannot edit the nav.
